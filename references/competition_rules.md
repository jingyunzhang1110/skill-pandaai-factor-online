# 第四届因子大赛评分规则（公开页面摘要）

来源：[PandaAI 第四届因子大赛规则](https://www.pandaaiquant.com/factorhub/fourthFactorCompetition/rules)，读取日期 2026-08-09。
平台结算数据优先；规则页更新时应重新核对本文件。

## 固定口径

- 股票池从全 A 开始，剔除 ST、当日一字板和当日停牌标的。
- 平台先对每个截面做 1%--99% Winsor 缩尾，再做 Z-score 标准化。
- 池内全部有效因子等权合成；有效因子数 `M < 5` 时无法生成有效组合，池子当月不计分。
- 池统一配置 1--10 个交易日调仓周期，提交后不可修改；所有因子和合成组合按同一周期采样、刷新信号和调仓。
- 合成多头组合按全市场综合因子排序，持有前 10%，等权配置；反向因子使用低值端。
- 单边交易成本为 0.3%；基准为中证全指指数。
- 每个调仓周期产生一条截面 RankIC；周期序列按月度聚合后进入评分。非调仓日沿用上一期信号，不产生新的调仓 IC。
- C 的 `Turnover` 是当月累计换手率：当月所有统一调仓日的组合换手率相加，不是单次换手率，也不是年化换手率。

## A：因子历史绩效（权重 20%）

单因子得分：

```text
S_i^A = |RankIC_i| × |ICIR_i| × IC胜率_i
```

历史记录范围是该因子的：

```text
样本内近 5 年 + 全部历史样本外
```

其中样本内近 5 年是提交/入池时点向前的五年历史，样本外部分是因子正式生效后继续产生的全部周期 IC 记录。两部分都按池统一调仓周期采样，并在月度聚合后计算指标。

`IC胜率` 不是简单的 `IC > 0`。它是有效统计周期中，IC 与因子有效方向一致且绝对值超过 `0.02` 的比例：

- 正向因子：`P(IC > 0.02)`；
- 负向因子：`P(IC < -0.02)`。

RankIC 与 ICIR 均按池统一调仓周期采样；RankIC 序列再按月度聚合。

池级原始得分为池内有效因子单因子得分的算术平均：

```text
rawA = sum(S_i^A) / M
NA = min(max(rawA / 0.08, 0), 1) × Decay
```

池龄规则：

- 生效 1--6 个月：`Decay = 1.00`，`NA` 额外封顶 `0.70`。
- 生效 7--12 个月：`Decay = 0.90`，不再额外封顶。
- 生效超过 12 个月：`Decay = 0.85`，不再额外封顶。

## B：样本外外推绩效（权重 35%）

```text
S_i^B = |RankIC_new| × |ICIR_new| × IC胜率_new
rawB = sum(S_i^B) / M
NB = min(max(rawB / 0.06, 0), 1)
```

B 只使用因子正式入库生效后新增的周期 IC，不复用历史旧记录；无 Decay、无额外封顶。提交前无法得到官方 B，只能在本地保存历史序列作为稳健性代理。正式入库后，应按统一调仓日持续记录新增 IC，不能用第二个研究对象冒充官方 B。

## C：多头组合绩效（权重 45%）

官方使用池内等权合成因子的多头组合月度日频净值账本：

```text
Rex_ann = (1 + Rex_month)^12 - 1
SR_ann = mean(Rex_daily) / std(Rex_daily) × sqrt(22) × sqrt(12)
rawC = max(Rex_ann, 0)
       / max(Turnover_month, 0.3)
       × SR_ann
       × (1 - 1.2 × MaxDD_month)
NC = min(max(rawC / 0.6, 0), 1)
```

- `Rex_month`：当月组合相对中证全指的超额收益。
- `Rex_daily`：当月全部日频超额收益序列；收益已计入单边 0.3% 交易成本。
- `Turnover_month`：当月所有统一调仓日换手率之和。
- `MaxDD_month`：当月日频净值曲线的最大回撤幅度，不是月末净值序列回撤。
- 月末数据完整后统一结算；收益非正时 `max(Rex_ann, 0)` 不产生正向 C 贡献。

实时预估中，SR 和 MaxDD 使用日频数据计算月度指标；日频 Sharpe 按日内每月约 22 个交易日、每年 12 个月折算，
即年化因子为 `sqrt(22) × sqrt(12)`。本地若只有调仓期曲线，只能输出调仓期 C 代理，不能称为官方 C。

CLI 的单因子结果可以提供分组超额收益、换手、Sharpe、回撤和序列图，因此能做 C 的单因子代理；但没有平台池级合成组合的完整月度日频账本时，不能宣称本地结果等于官方 `NC`。

## 综合积分

```text
Comb = 0.20 × NA + 0.35 × NB + 0.45 × NC
monthly_points = min(Comb × 40000 × newcomer_bonus, 40000)
```

- 新人注册三个月内月度结算积分乘 `1.10`，单月仍封顶 `40000`。
- 有效因子数 `< 5` 时当月积分冻结，历史累计保留。
- 因子修改会清零并重新积累其生效后的 IC 记录；具体生效与删改窗口以平台后台为准。

## 本地能做什么

### 可做的代理

使用 `factor_result` 的 RankIC 序列、分组收益、换手、Sharpe、回撤和下载的因子 CSV，可以本地计算：

- A 的五年历史 RankIC 月度代理；
- 分年/分阶段的 RankIC 稳定性与符号一致性；
- 单因子 C 的多头端收益、换手成本和风险代理；
- 多个候选的相关性、冗余和简单组合候选。

### 不可精确复现的部分

- 提交前没有真实的 B 生效后新增记录；
- C 需要平台池级等权合成因子和完整月度日频净值账本；
- 平台标准化、股票池当日剔除、结算时点和新人/池龄状态以后台为准。
- 分析工具的 `沪深全A` 与比赛的中证全指口径一致，且 ST、停牌、当日一字板过滤按官网规则处理；当前 CLI 创建工作流
  仍固定中证1000，不能用来直接复现全 A 比赛池。

## 因子池生命周期与合规

- 建池当天可以自由增删；提交因子池后，修改/删除仅限每月 1--3 日窗口。
- 新增因子从下一个统一调仓日起进入合成；其 NB 不包含入池前历史。
- 修改公式或代码的因子按新因子处理，样本外累计清零；仅改名称不会清零，但不要在删改窗口内触发更新。
- 删除因子后，历史累计积分保留；池内正常提交 5 个及以上有效因子才有资格计分。
- 有效因子没有公开的 IC、显著性或相关性硬门槛，但不能是公式/代码重复或明显刷量异常，后台会人工排查。
- 人工参赛者可以使用本地 AI 工具辅助研发，由本人确认和提交即可；每日新增因子上限 50 个，人工和 Agent 都适用。
- 每日新增统计以北京时间 07:00 为切换点：07:00 前计入前一天，07:00 后计入当天。
- 因子表达式对其他选手不可见，官方可查；知识产权仍归参赛者，赛事运营、回测、反作弊和榜单公示所需使用按官方授权执行。

### 五因子组合选择

用户可能有 6 个候选，想枚举全部 5 因子组合并选取 C 最高者。这是合理的提交前需求，但当前
`pandaai-cli` 只提供单因子创建、运行和结果查询，没有因子池创建、组合回测或池级日频账本接口。

正确流程是：

1. 所有候选用相同的近 5 年窗口、池调仓周期、10 组和股票池，先计算 A 代理和实际多头端的成本筛选；
2. 下载候选因子值，计算截面 Spearman 相关，删除高度冗余的候选；
3. 枚举 `C(n, 5)` 个组合，按平均 A、最低相关性、成本筛选和经济机制多样性形成**待验证组合**；
4. 对每个待验证组合取得平台池级日频账本，再按官方 C 的月度公式排序；
5. 有效因子少于 5 个时不提交，因为官方池当月不计分。

不要把五个单因子的 C 相加、平均，或用五个单因子收益的加权和替代组合 C。平台先对每个截面因子
Winsorize、Z-score、等权合成后再排序，组合排序和换手率不是单因子结果的线性组合。仅凭 CLI 下载的
单因子值 CSV 也缺少平台动态股票池、日收益和池级执行账本，不能精确重建官方 C。

本地评估只能标注为“比赛规则代理”，用于 shortlist 和复盘，不得宣称预测或复制官方积分。

## 与普通挖掘的关系

比赛评分是用户选择的进阶评估模式，不是默认挖掘目标。普通流程仍然遵循公式优先、Python 只在公式难以清楚表达时切换，并按用户指定的收益、风险、换手、容量或可解释性排序。

## 提交前的两条候选路径

当用户明确以比赛为目标时，先说明两条路径可并行使用，但不要把本地历史结果误称为 B：

- **A-first（默认）**：统一用提交日前近 5 年、池的调仓周期和 10 组口径，按 A 历史代理筛选；再要求实际多头端在扣成本后的 C 历史代理不过度恶化。这是对长期稳定性的下注。
- **B-regime（可选）**：完整 5 年未必排名最高，但在与当前市场状态相似的历史阶段表现突出；用户明确选择后，单独报告所选状态、样本长度、筛选次数和失效条件。这是对当前环境延续的下注，可能主动牺牲 A。

两条路径最终都进入同一个正式因子池。正式入池后新增的真实 RankIC 才形成官方 B；不要为了这两条研究路径创建两个正式提交工作流。
